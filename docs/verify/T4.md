2. `syncLocked` clears `sync_error` only on a successful re-index. If a sync failed and the file then goes back to the stored hash, the early "hash unchanged" path updates mtime and size but leaves the old `sync_error` showing. This is a rare edge, and the next real change clears it.
3. `PipelineRow::insert` is not chunked, unlike tasks. A pipeline with about 8000 rows would exceed the placeholder limit. Unrealistic.
